本章系统性回顾本研究涉及的关键技术，包括舆情数据采集与预处理、主题模型及其评价指标、稀疏注意力机制、预训练语言模型在情感分析中的应用、以及大模型轻量化微调方法与工程实现要点。文献回顾侧重于方法论的原理、适用条件与局限，并在必要处指出本研究所采用技术的理论依据与工程取舍。

\section{舆情数据采集与预处理}
\label{sec:data_collection}

舆情数据采集的目标是获得能够代表研究问题域的高质量文本与元数据。常见数据来源包括平台公开 API、网页抓取与开放语料库。不同来源在数据完整性、权限约束和可重复性方面存在差异：API 常提供结构化且带有时间戳的记录，网页抓取能够获取更丰富的历史信息，而公开数据集有利于可复现性与基线比较。

在采样策略上，需根据研究目标选择合适的方法，例如按时间窗口抽样用于分析舆情演变、按商品类目或品牌分层抽样用于横向比较。为减少样本偏倚，应考虑采用分层抽样或基于影响力（如销量或曝光量）加权抽样。对于监督学习任务，构建训练集时还必须考虑标签分布（类别不平衡）和长尾类目的样本稀缺性，并采用过采样、欠采样或类权重等方法予以缓解。

数据清洗是保证下游分析有效性的前提，包括统一字符编码、HTML 与噪声字符清除、表情与特殊符号规范化、以及基于文本相似度或哈希的去重处理（例如 MinHash 或基于 TF-IDF 的阈值过滤）。此外应保存完整的元数据（采集时间、来源、商品ID、用户ID、抓取批次等）以支持事后溯源与分层分析。

工程实现方面，动态渲染页面的抓取通常借助 Puppeteer/Playwright，结合代理池、请求节奏控制与断点续抓机制，以提高抓取的稳定性与合规性。对于存在严格反爬策略的平台，需要在法律与平台规则允许范围内设计容错与重试策略，并记录抓取日志以便排查并发问题。

\section{主题模型：方法、评价与适用性}
\label{sec:topic_models}

主题建模旨在从大规模文本中发现潜在话题结构。生成式模型（如 LDA）与非参数贝叶斯扩展（如 HDP）是经典方法。LDA 需要预设主题数 $K$，在短文本与高噪声场景下常出现主题稀疏、可解释性差的问题；HDP 通过非参数先验自动推断主题数，更适合类目多样或主题分布未知的语料，但其推断复杂度与工程实现要求更高。

在电商评论场景，主题模型的实际应用包括话题提取、故障/投诉类别识别及与评分的关联分析。为提高主题可解释性和下游任务性能，常采用以下工程实践：

- 预处理与短文本扩展：通过上下文拼接、句子聚合或外部知识扩展短文本长度，改善主题稳定性；
- 混合模型或神经主题模型：结合词向量或 Transformer 表示，构建基于神经网络的主题模型以捕捉更细粒度语义；
- 后处理与人工审阅：对主题关键词进行人工校正或合并，以提升业务可用性。

主题质量的评价通常综合自动指标和人工评估。自动指标包括主题一致性（Coherence）、困惑度（Perplexity）以及基于嵌入的语义相似性度量；人工评估以主题关键词的可解释性与下游任务（如基于主题的分类或检索）的实际表现为准。

\section{稀疏注意力机制与长序列表示}
\label{sec:sparse_attention}

Transformer 自注意力的二次复杂度在处理长序列时成为瓶颈。稀疏注意力通过结构化或可学习的稀疏模式降低计算与内存开销，同时尽量保留关键信息。常见方法包括局部窗口注意力、全局 token 机制、块状稀疏与可学习稀疏化（例如 Sparse Transformer、Longformer、BigBird 等），每种方法在信息保留能力与实现复杂度上存在权衡。

在本研究中，稀疏注意力的价值体现在两方面：一方面作为文本表示层，生成适合主题建模的段落/句子级向量以保留长程上下文；另一方面可与主题模型结合，通过注意力权重引导主题分配，以提高主题的稀疏性与可解释性。

\section{预训练语言模型在情感分析中的应用}
\label{sec:pretrained_models}

基于 Transformer 的预训练模型（如 BERT 及其变体）已成为情感分析的主流方法。其优势在于通过大规模语料学习到的上下文感知表征能够有效处理否定、修饰以及隐含情感表达。情感分类通常通过在任务数据上进行监督微调实现，评估指标以 Precision、Recall、F1 与 AUC 等为主。

细粒度情感任务（包括方面级情感分析、情感强度评分与多标签情感判定）通常需要在模型架构或数据标注上做相应设计，例如采用联合模型同时预测方面与极性，或引入多任务学习以共享表示并提高泛化能力。

针对资源受限或大模型部署场景，轻量化微调方法（如 LoRA、QLoRA）通过仅学习低秩适配参数或在量化模型上微调少量参数，实现显存与计算开销的大幅降低，从而在工程上具有显著价值。

\section{大模型轻量化微调与工程实践}
\label{sec:qlora}

QLoRA 将量化技术与低秩适配结合，允许在量化后的模型上以极小的额外参数完成微调。工程上需注意量化精度对下游任务性能的影响、LoRA 的秩选择对模型容量与可训练性的权衡，以及训练过程中的稳定性措施（学习率调度、梯度裁剪等）。

部署方面，建议结合混合精度、模型并行与批量推理优化推理吞吐；并通过持续监控（包括输入分布漂移检测与在线评估）维护模型长期性能。

\section{系统实现与技术栈评述}
\label{sec:tech_stack}

从工程实现角度，推荐的组件包括：数据采集与预处理管线（Scrapy/Playwright + ETL 作业）、存储层（关系型数据库 + Elasticsearch/文档库）、模型训练与服务化框架（PyTorch + Hugging Face + FastAPI/TorchServe）、以及可视化与监控平台（ECharts/Prometheus + Grafana）。实现要点包括模块化设计、可复现的数据版本控制以及自动化的模型验证与部署流水线。
