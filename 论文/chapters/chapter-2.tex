\chapter{相关技术综述}
\label{ch:survey}

\section{舆情数据采集技术}
\label{sec:data_collection}
\subsection{数据来源与采样策略}
电商评论数据的主要来源包括平台开放接口、网页抓取以及公开数据集。平台接口通常提供结构化字段但受限于权限，网页抓取可获得更全面的历史评论，公开数据集便于快速实验与基线对比。在采样策略上，常见做法有按时间窗口抽取以研究舆情演变、按商品类目或品牌分层抽样以保证代表性，以及基于销量或热度筛选以关注高影响力样本。构建训练集时还需考虑正负样本平衡与长尾类目的采样策略。

\subsection{爬虫设计与反爬策略}
爬虫实现可以采用 Scrapy 作为抓取框架，结合 Playwright 或 Puppeteer 处理动态渲染页面。设计要点包括请求节奏控制、代理池与动态请求头、并发限制与重试策略。面对反爬机制，应实现验证码识别或绕过、登录态维护和 IP 轮换，并对抓取错误进行记录与容错处理。为保证抓取稳定性，还应实现断点续抓、增量抓取和抓取任务的监控告警。

\subsection{数据清洗与去重}
采集到的原始评论通常包含 HTML 标签、表情、广告和重复条目，需在入库前进行清洗。常见流程包括统一字符编码、去除 HTML 与多余空白、表情和特殊符号的规范化、基于哈希或文本相似度的去重（例如 MinHash 或 TF-IDF+阈值），以及对过短或非中文/非目标语言评论的过滤。对于含有噪声的评论，可采用规则或模型化的方法识别并剔除，另外保留完整的元信息用于后续分析。

\subsection{数据存储与元数据管理}
评论数据同时包含结构化字段（评分、时间、商品ID、用户ID）和非结构化文本，推荐采用混合存储架构：关系型数据库保存交易与业务表，文档型数据库或搜索引擎（如 Elasticsearch）用于全文检索与聚合分析。元数据应包含时间戳、采集来源、商品类目、用户标签与抓取批次，以支持分层统计与数据溯源。针对历史数据应设计分区策略并考虑冷热数据分层存储以优化查询性能。

\section{主题模型（HDP / LDA）}
\label{sec:topic_models}
\subsection{LDA 概述与适用性}
LDA 是一种经典的生成式主题模型，通过词-主题和主题-文档分布建模文本语料的潜在主题结构。在电商评论场景，由于文本较短且噪声较多，LDA 在直接应用时常表现出主题稀疏和主题分散的问题。此外，LDA 需要事先指定主题数 K，这在实际中往往难以确定，需要借助指标选择或人工试验来确定合适的主题数。

\subsection{HDP：自动确定主题数}
层次狄利克雷过程（HDP）属于非参数贝叶斯方法，能够在训练过程中依据数据自动推断主题数量，免去手动选择 K 的步骤。HDP 对异构或类目众多的评论语料更具适应性，但其推断复杂度通常高于 LDA，工程上需要采用变分推断或高效采样算法以提升训练速度，并结合主题后处理提高可解释性。

\subsection{主题模型在电商评论中的应用}
主题模型可用于自动提取商品评论中的关键话题，如功能诉求、质量问题與使用体验等，帮助产品和运营识别高频投诉点与改进方向。结合评分与时间信息，可以分析特定话题与负面情感的关联性，支持按类目或按商品聚类分析，从而为售后与产品迭代提供数据驱动的决策依据。

\subsection{主题质量评价}
评价主题质量既可采用自动指标也需辅以人工检验。常用自动指标包括主题一致性（Coherence）和困惑度（Perplexity），其中一致性更贴近语义可解释性。为了确保业务可用性，应结合人工标注、主题关键词的人工审阅以及下游任务（例如基于主题的分类或召回）的性能评估。

\section{稀疏注意力机制}
\label{sec:sparse_attention}
\subsection{设计动机：长文本与效率问题}
Transformer 的自注意力机制在序列长度较大时会产生二次计算与内存复杂度，面对合并评论或跨评论聚合的长文本场景会导致显著的性能瓶颈。因此在需要保留长程依赖信息的同时，还必须控制计算资源消耗，促使稀疏化注意力成为一个实用的折中方案。

\subsection{常见稀疏注意力方案}
典型的稀疏注意力方案包括局部窗口注意力、全局 token 或全局节点、分块稀疏以及可学习的稀疏模式。局部窗口机制通过限制注意力的计算范围来降低复杂度，全局节点用于连接远距离信息，分块方法将序列拆分为多个块并在块间偶尔建立通信。不同方案在实现复杂度与信息保留上有权衡，需根据具体任务与资源约束选择合适策略。

\subsection{稀疏注意力与主题模型的融合点}
稀疏注意力可作为表示学习层，为主题模型提供更紧凑且能保留长程信息的文本向量。实践中可以先用稀疏注意力的 Transformer 提取句子或段落级别向量，再将这些向量作为主题模型的输入，从而兼顾长文本信息与主题建模的统计稳定性。此外，稀疏注意力也可用于加速基于神经的主题模型或在推断阶段进行重要位置的优先计算。

\section{预训练模型与情感分析}
\label{sec:pretrained_models}
\subsection{预训练模型简介（BERT 等）}
基于 Transformer 的预训练模型（如 BERT、RoBERTa 及其中文变体）通过大规模无监督语料学习通用语言表示，这些表示在下游情感分类、观点抽取等任务中表现优异。预训练模型能够捕捉上下文依赖与细粒度语义，有助于解决电商评论中存在的否定、修饰和复杂语义表达问题。

\subsection{情感分类与微调实践}
情感分类通常采用监督微调的方式，在标注数据上微调预训练模型。关键实践包括建立高质量的标注集、处理类别不平衡（如加权损失或重采样）、以及采用合适的评估指标（Precision、Recall、F1）。在少样本或领域迁移场景，可结合数据增强、迁移学习或半监督方法提升模型鲁棒性。

\subsection{情感判定的细粒度任务}
电商场景下常见的细粒度任务包括方面级情感分析（识别商品属性并判定该属性的情感）、情感强度评分以及多标签情感判定。实现方面级分析通常需先进行方面抽取再进行属性級别的情感分类，或采用联合模型同时预测方面与情感极性，从而为产品改进提供可操作的诊断信息。

\section{大模型轻量化微调（QLoRA）}
\label{sec:qlora}
\subsection{QLoRA 概念与工作流程}
QLoRA 通过在量化后的大模型上应用低秩适配（Low-Rank Adaptation）技术，实现显存占用显著降低的微调方法。其核心思想是在不更新原始大模型权重的前提下，增加少量可训练的低秩参数，从而在保持性能的同时减少训练和部署成本。通常流程包括模型量化、插入低秩适配模块、在目标任务数据上微调这些适配参数并评估效果。

\subsection{在资源受限环境的部署策略}
在资源受限的部署环境中，可结合混合精度、梯度累积、模型并行与显存分片技术降低训练峰值显存。推理阶段可采用更激进的量化、知识蒸馏或剪枝手段减少模型大小与延迟。实际工程中常将微调后的轻量化模型封装成服务端点，并辅以批量推理、缓存和异步队列以满足高并发场景。

\subsection{评估与泛化}
微调后模型应在跨类目和跨时间段的数据上进行验证以评估泛化性能。常用方法包括时间切分的留出验证、在未见类目上进行零/少样本测试以及监控在线输入分布与模型置信度变化。若观察到性能退化，可通过持续学习或定期增量微调来恢复性能。

\section{系统开发技术栈}
\label{sec:tech_stack}
\subsection{后端与服务化}
后端服务可选择成熟框架实现，如 Java 的 SpringBoot 或 Python 的 FastAPI/Flask。模型服务化建议采用标准化接口（REST 或 gRPC），并使用模型服务器（如 TorchServe 或自建推理服务）以支持模型版本管理与热更新。

\subsection{前端与可视化}
前端可采用 React 或 Vue 等现代框架实现交互式控制台，数据可视化建议使用 ECharts 或 D3 来展示情感趋势、主题分布、热词云和筛选对比视图。可视化设计应保证交互便捷、支持多维筛选并能导出报表。

\subsection{存储与消息队列}
建议采用关系型数据库（MySQL）存放业务与交易数据，Elasticsearch 用于全文检索與聚合查询，MongoDB 或 Redis 可作为缓存或半结构化数据存储。Kafka 或 RabbitMQ 可用于解耦采集、预处理与模型推理的异步流水线。

\subsection{部署与监控}
生产环境部署建议使用 Docker 容器化并配合 Kubernetes 进行编排与弹性伸缩。监控应覆盖服务可用性、延迟、吞吐以及模型相关指标（输入分布漂移、置信度分布），并集成日志系统与告警机制以便快速定位与响应问题。
