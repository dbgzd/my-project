\chapter{系统实现}
\label{ch:implementation}

本章描述第~3~章提出方法的实现细节，涵盖开发环境与依赖、各模块的工程化实现、性能优化与工程实践要点。文中重点说明数据采集与预处理流水线、稀疏注意力增强的 Sparse-HDP 实现、基于 QLoRA 的情感模型微调与部署，以及前端可视化与运维设计。所有实现均遵循可复现性与模块化设计原则，训练与推理脚本、配置与运行日志被组织在项目的 `scripts/` 与 `configs/` 目录下以便复现。

\section{开发环境与技术栈}
\label{sec:dev_env}

开发环境采用主流开源工具链以保证可维护性与跨平台可复现性。关键技术栈如下：

- 开发语言：Python 3.8+（数据处理、模型训练、微服务）与 JavaScript/TypeScript（前端交互）。
- 深度学习框架：PyTorch（模型训练与推理），Hugging Face Transformers（预训练模型加载与 LoRA 接口）。
- 微调与量化：使用 bitsandbytes 与 peft 库实现 QLoRA 工作流。 
- 数据处理：pandas、numpy、scikit-learn、jieba（中文分词）、spaCy（可选）。
- 搜索与索引：Elasticsearch / OpenSearch 用于全文检索与聚合查询。 
- 后端服务：FastAPI（REST API）、Gunicorn + Uvicorn（服务部署）。
- 消息与调度：Kafka（队列）与 Airflow（定期训练/ETL 调度）。
- 容器与编排：Docker + Kubernetes；CI/CD 使用 GitHub Actions。 
- 可视化：React + ECharts，用于仪表盘及交互式图表。

为保证实验可复现，训练与评估环境使用 `requirements.txt` 和 `environment.yml`（或 `pyproject.toml`）进行依赖管理，模型训练脚本支持传入随机种子与日志记录以方便重现实验结果。

\section{数据采集模块实现}
\label{sec:impl_data_collection}

数据采集模块实现采用任务驱动与队列化的设计。核心组件包括：采集任务管理器、爬虫适配层、代理管理与入队服务。

实现细节：

- 任务管理器：基于调度系统（Airflow）下发采集任务，任务元数据包括目标站点、时间窗口、爬取频率与抓取策略。任务通过 Kafka 写入 `topic:raw\_comments`，供下游预处理消费。 
- 爬虫适配层：为不同站点提供插件式抓取器（Scrapy + Playwright），抓取器负责登录、页面渲染、翻页与反爬策略处理；抓取结果首先写入持久化存储（原始数据仓）并向 Kafka 发送索引消息。
- 代理与速率控制：实现多级代理池，结合动态请求头与请求间隔策略以降低被封禁风险；对频繁失败的任务进行退避重试并记录异常日志。
- 容错与监控：实现断点续抓（记录已抓取 ID 与时间戳）、任务重试计数与抓取质量统计（成功率、重复率）。所有抓取事件与错误被发送到集中式日志系统（ELK），并在异常阈值触发告警。

数据落盘格式与接口：原始记录以 JSON Lines 写入对象存储（按日期分区），并保留原始 HTML、抓取时间、请求参数与爬取任务 ID，以便事后审计与追溯。

\section{文本预处理模块实现}
\label{sec:impl_preprocessing}

预处理模块作为模型输入的中台服务，确保文本质量与特征一致性。模块以流式与批处理并行的方式实现，关键步骤包括：编码与语言检测、文本清洗、分句与分词、去重、以及特征抽取（TF-IDF、嵌入向量）。

实现要点：

- 编码与语言检测：使用 Unicode 规范化并对非目标语言进行过滤（langdetect / fastText 语言检测模型）。
- 文本清洗：正则过滤 HTML 与脚本、表情与噪声字符替换、URL/邮箱脱敏、对敏感信息进行标记或脱敏处理。 
- 分句与中文分词：中文使用 rule-based+统计的混合分词（jieba + 自定义词典），对评价类句子做短文本聚合以提高主题模型效果。 
- 去重：采用基于 MinHash 的近似去重用于大规模流式数据，批处理场景下结合 TF-IDF 余弦相似度做精排去重。 
- 特征与向量化：提供两类特征：稀疏特征（TF-IDF）与密集向量（基于预训练 BERT 的句向量）；向量化服务采用批量异步处理并缓存常见文本的 embedding。 

为保证处理性能，预处理模块采用多进程与分布式任务队列，关键参数（如最小长度、停用词列表、聚合窗口）由配置文件管理，便于实验对比。

\section{Sparse-HDP 主题模型实现}
\label{sec:impl_sparse_hdp}

稀疏注意力增强的 Sparse-HDP 实现在实践中分为离线训练与在线推理两部分。训练模块基于变分推断实现，并在关键计算中引入 entmax/sparsemax 操作以保证主题稀疏性。

主要实现细节：

- 数据准备：训练数据以清洗后文本为单位，采用滑动窗口或句子聚合扩充短文本，使每个训练样本包含足够上下文。词表采取频次截断并使用子词或 BPE 以处理未见词。
- 模型实现：核心模型使用 PyTorch 实现变分推断网络，主题中心 $\phi_k$ 使用可训练嵌入矩阵表示；注意力计算使用矩阵乘法加温度缩放，随后应用 entmax/sparsemax 以获取稀疏分配。实现中使用 `torch.nn.functional` 的自定义 entmax 函数以保证数值稳定性。
- 训练优化：采用小批量随机变分推断（SVI），结合学习率调度与梯度裁剪；使用混合精度训练以提高 GPU 利用率。为减少显存占用，对长文采用分块处理并在块级别汇总统计量。
- 在线推理：推理服务封装为 REST API，输入为清洗后文本或向量，输出为主题分布与高权重主题词。推理通过预加载的主题中心与轻量化注意力计算实现低延迟返回。

性能与可扩展性：训练过程支持数据并行与模型并行的混合策略；推理节点采用多副本与批量聚合以应对高并发请求。模型版本与主题演进通过 `topic\_model\_versions` 表记录，以便回溯与比较。

\section{QLoRA 大模型情感分析实现}
\label{sec:impl_qlora}

情感分析模块采用 QLoRA 流程在量化模型上进行低成本微调。实现分为数据准备、微调训练与在线推理三部分。

实现要点：

- 数据准备：构建句子级与文档级标注集，数据格式以 JSON Lines 保存，字段包括 `id`, `text`, `labels`, `meta`。对于弱监督场景，使用情感词典与规则生成初始标签，并用人工标注的小样本做校准。 
- QLoRA 微调：使用 bitsandbytes 对基础模型进行 4-bit 量化，利用 PEFT/LoRA 在量化模型上插入低秩适配层训练。训练脚本（如 `scripts/train\_qlora.py`）支持分布式训练、梯度累积与学习率调度。 
- 部署与推理：微调后模型导出为可加载的 checkpoint，推理服务封装为 FastAPI 应用并部署在 GPU 池中；对延迟敏感的场景可使用更低位量化或蒸馏后的轻量模型。 

评估与监控：在训练期间记录训练/验证集的精度、F1、损失曲线与置信度分布；上线后持续监控置信度分布与输入分布漂移，必要时触发增量微调。

\section{前端可视化与报表模块实现}
\label{sec:impl_frontend}

前端采用组件化设计，主要包括：趋势分析视图、主题分布与热词云、示例评论检索与导出、以及告警配置界面。前端通过 REST API 拉取聚合数据，并使用 ECharts 绘制交互图表。

实现细节：

- 可视化组件：独立的 React 组件用于时间序列（折线图）、主题分布（堆叠柱状图/词云）、情感分布（饼图/热力图）与表格展示（可排序、分页）。
- 交互与过滤：支持按时间区间、主题、商品 ID 与关键词联合过滤，并能将当前视图导出为 CSV 或图片。 
- 性能优化：对于大时间窗口的聚合查询使用预计算的聚合视图与 Elasticsearch 聚合 API；前端对大型数据进行分页与增量加载以降低内存占用。
